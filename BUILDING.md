# Building FotoAsist GC

Everything below works on a clean Mac with nothing but this repository. No other repository, account, key, certificate or service is needed to build, test and run the application.

## Requirements

- macOS 13 or later (the subject mask needs macOS 14 at run time).
- Xcode command line tools with Swift 5.9 or later (`xcode-select --install`).
- An internet connection the first time, to download the LibRaw source archive (about 1 MB, verified by SHA-256).

## Commands

```bash
scripts/swift.sh test                 # build LibRaw if needed, then build and run all tests
scripts/swift.sh build                # debug build
scripts/swift.sh run PhotoAssist      # run from the build directory
scripts/make_app.sh                   # release build → "FotoAsist GC.app", ad-hoc signed
scripts/make_pkg.sh                   # installer package, unsigned
```

Generated files go to `.build-out/` in the repository (ignored by Git). To put them somewhere else, for example on an external disk:

```bash
export FOTOASIST_BUILD_ROOT=/path/to/build-root
```

| Variable | Meaning | Default |
|---|---|---|
| `FOTOASIST_BUILD_ROOT` | where LibRaw, the SwiftPM scratch directory, the app and the package are written | `<repository>/.build-out` |
| `FOTOASIST_ARCHS` | compiler architecture flags for LibRaw | `-arch arm64 -arch x86_64` |
| `FOTOASIST_APP_ARCHS` | architectures of the app binary, e.g. `"arm64 x86_64"` for a universal build | the Mac you build on |
| `FOTOASIST_SWIFT_FLAGS` | extra SwiftPM flags, e.g. `--disable-sandbox` inside an already sandboxed build | none |
| `FOTOASIST_BUNDLE_ID` | bundle identifier of the app you assemble | `dev.gordas.photoassist` |

The version is the single line in the `VERSION` file; `scripts/make_app.sh` writes it into the application.

## Layout

```
core/                     Swift package (no external Swift dependencies)
  Sources/CPhotoCore      image mathematics, C++17, one C header
  Sources/PhotoCore       catalog (SQLite), import, previews, localisation, diagnostics
  Sources/PhotoRaw        RAW decoding through LibRaw, float image I/O
  Sources/PhotoResolve    processing pipeline, adjustments, geometry, retouching, analysis
  Sources/PhotoAccess     open-edition feature policy and update check
  Sources/PhotoAssistUI   the SwiftUI interface
  Sources/PhotoAssist     the application entry point
  Sources/PhotoDecode     a small command line decoder
  Tests/                  unit tests
scripts/                  build scripts
packaging/                application icon, installer licence text
```

The source comments and the source texts of the interface are in Romanian (the application is translated to English and Spanish in `core/Sources/PhotoCore/LocalizationTables.swift`). Contributions may use English.

## Tests

`scripts/swift.sh test` uses synthetic data generated by the tests themselves. No photographs are stored in this repository.

Some tests exercise real RAW files. They are skipped unless you point them at your own files:

| Variable | Used for |
|---|---|
| `GDC_PA_RAW_DIR` | a folder with RAW files of your own |
| `GDC_PA_SCRATCH` | a writable folder for their output |
| `GDC_PA_FUJI_RAF` | one Fujifilm RAF file |

Never commit photographs, and never attach private photographs to an issue; describe the camera model and the symptom, or attach a file you are allowed to publish.

## The two editions and the edition switch

This repository is the open-source edition. It is compiled with `GDC_PA_OPEN_EDITION` (Swift) and `GDC_PC_OPEN_EDITION` (C++), both set in `core/Package.swift`. The call sites of the modules that exist only in the full edition are excluded by those flags; you will see them in `#if` / `#ifdef GDC_PC_PREMIUM` blocks. Those blocks are never compiled here and the files they would include are not in this repository. `Edition.full` (`core/Sources/PhotoResolve/Edition.swift`) is `false` in this edition and hides the corresponding panels.

Please do not remove those blocks in a pull request: they keep the two editions on one code base, so fixes made here reach both.

## Official releases

Pull request checks and official releases are separate on purpose.

- **Continuous integration** (`.github/workflows/ci.yml`) builds and tests every pull request on a GitHub-hosted macOS runner. It uses no secrets and has read-only permissions, so it runs the same way for forks.
- **Official packages** are built by the maintainer, on the maintainer's Mac, from a tagged commit of this repository: `scripts/make_app.sh` and `scripts/make_pkg.sh` with a Developer ID identity (`FOTOASIST_SIGN_APP`, `FOTOASIST_SIGN_INSTALLER`), then Apple notarization and stapling. The signing identities and notarization credentials are not in this repository and are not available to any workflow here.

A package you build yourself is not signed with the project's Developer ID. It runs on the Mac that built it; on another Mac, Gatekeeper will ask the user to allow it.

To check that an official package matches the source: its version is the tag it was built from, and `FotoAsist GC.app/Contents/Info.plist` records the commit in `GDCPABuild`.
